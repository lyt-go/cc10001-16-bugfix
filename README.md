# 网络数据采集管理平台

面向网页数据接入、定时增量采集、抽取规则管理、代理调度、限速策略、失败重试与采集结果验证的网络数据采集工程管理平台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

## 登录态 / 反爬 / 采集任务的联动状态

三个模块的会话结论由后端统一算出，前端只展示，不再自行推断可用性。

- 登录凭证按 `草稿 → 验证中 → 有效 → 已过期` 顺序流转：
  - 只有 `验证中` 能通过验证结果动作（`标记有效` / `验证通过`）收口；`草稿` 和 `已过期`
    都不能被直接点成 `有效`。
  - `已过期` 要恢复 `有效` 必须先 `提交验证`，验证通过后才恢复。
  - 有效期已过的 `有效` 凭证在读取列表/详情时自动落到 `已过期`，避免继续使用旧 Cookie。
  - 验证失败保留 `失败原因`，且 `最近验证时间` / `最近验证成功时间` 不被改写。
  - 动作在 `store.lock` 内完成，同一凭证并发提交/并发验证只允许一次成功。
- 反爬策略按 `草稿 → 策略测试中 → 已启用 → 已失效` 顺序流转：
  - `草稿`、`已失效` 只能先提交策略测试，测试未通过不能启用。
  - 策略测试失败/启用失败都会保留 `测试失败原因`。
  - 提交测试前校验 UA 至少覆盖三种浏览器、Referer 指向目标站点首页、验证码识别有明确
    配置；错误配置不能被直接启用。
- 采集任务启动前读取登录态与反爬策略的同一份结论（`GET /api/taskcrawl/readiness/{id}`）：
  - 两条绑定关系冲突时，按最近一次验证成功的登录凭证判定；策略取最近测试通过的。
  - 任一不可用时，列表/任务卡返回 `会话状态=不可用`、`任务卡状态=待重新验证`（凭证问题）
    或 `待策略测试`（策略问题）以及 `不可启动原因`，启动动作同步被拒绝。
  - 列表与详情、启动动作复用同一个 `readiness()` 结果，避免列表显示可用、任务却拿到旧配置。
